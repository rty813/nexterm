# 插件商店：发布流程

插件商店是一个静态文件夹，由中继在 `/store/` 提供（见 `relay/README.md` 的“插件商店”一节）。发布者在自己的电脑上签名，中继只负责存放文件。商店是公开的，不需要令牌。Nexterm 客户端第一次添加商店时，自动信任目录里声明的公钥，之后的目录都必须由这把公钥签名。

```
store/
├── index.json          插件目录：插件、版本、文件位置、sha256、权限
├── index.json.sig      对 index.json 原始字节的 Ed25519 签名（base64）
└── packages/<插件 ID>/<版本>.nexterm-plugin
```

## 规则

- 版本号必须是语义化版本（`x.y.z`）。已发布的版本不能修改内容，也不能发布比当前最新版本更低的版本：要改就提高版本号。
- 旧版本的包会一直保留。`seq` 每次有变化就加 1，客户端会拒绝比已见过的更旧的索引。
- 插件目录里可以放 `store.json`，内容是商店里展示的简介（必须同时有中文和英文）、作者、主页和标签：

  ```json
  {"description": {"zh": "…", "en": "…"}, "author": "…", "homepage": "https://…", "tags": ["ssh"]}
  ```

- 私钥只放在发布者电脑上（或 CI 的受保护变量里），不要放到中继服务器上，也不要提交进 git。

## 命令

```bash
# 只需执行一次：生成签名密钥，记下打印出来的公钥和指纹
node scripts/plugin-store.mjs keygen --out ~/.nexterm-store/<商店>.key

# 发布：先从服务器拉取当前商店，再追加插件、签名，最后推送回服务器
STAGE=~/.nexterm-store/<商店>
node scripts/plugin-store.mjs build --store "$STAGE" --key ~/.nexterm-store/<商店>.key [--name "<商店名>"] <插件目录>...
node scripts/plugin-store.mjs verify --store "$STAGE" --public-key "<公钥>"
```

`build` 会先用私钥对应的公钥验证已有的 `index.json`，签名对不上就停止，不会在被篡改过的目录上继续追加。没有任何变化时，索引保持原样，不会重新签名。

## 推送到中继

中继部署目录下的 `store/` 以只读方式挂载进容器，拷贝文件后立即生效，不用重建镜像。推送时先传插件包，最后传 `index.json.sig` 和 `index.json`：

```bash
SSH="ssh -i ~/.ssh/<密钥> root@<中继服务器>"; R=<部署目录>/store
$SSH "tar -C $R -cf - ." | tar -xf - -C "$STAGE"                       # 拉取
tar -C "$STAGE" -cf - packages | $SSH "tar -xf - -C $R"                 # 推送插件包
tar -C "$STAGE" -cf - index.json.sig index.json | $SSH "tar -xf - -C $R"  # 最后推送索引
```

推送后，从 `/store/` 下载文件，再运行一次 `verify` 确认。

## 分发给用户

把商店地址发给用户即可，例如 `https://<中继>/store/`。用户在「设置 → 插件 → 商店 → 添加商店」里粘贴这个地址，客户端会下载目录并验证签名，验证通过就直接添加，同时记住目录里的公钥。已经添加过商店的用户，也可以在商店条目上点“复制商店地址”转发给同事。

商店对任何知道地址的人公开，插件里不要放密码、令牌等敏感信息。

## 客户端行为

- 商店列表和已安装的插件都保存在数据目录，属于配置同步的“插件”类别，换电脑同步后可以直接使用。
- 公钥在第一次添加时自动信任，之后不会变。如果商店换了签名密钥，旧条目会报“签名公钥不一致”，删掉商店重新添加即可。
- 主窗口启动几秒后，会自动检查所有已启用的商店。有更新时，右下角弹出提示条：
  - 点“全部更新”：权限没有变化的插件直接更新；新版本增加了权限的，会进入插件页等待确认。
  - 点“查看”：打开插件列表。
- 一个插件只从安装它的那个商店接收更新和撤销。从另一个商店安装同 ID 的插件，会在确认界面上提示来源变更。
- 索引里的 `revoked`（`{"id": "…", "versions": ["1.0.0"] 或 ["*"], "reason": "…"}`）会让已安装的对应版本自动停用，并显示撤销原因。
- 每个商店见过的最大 `seq` 记在本机，比它旧的索引会被拒绝。
