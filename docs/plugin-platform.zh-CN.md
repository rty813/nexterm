# Nexterm 原生插件平台方案与实施状态

Nexterm 提供可本地安装的实验性插件平台。开发者通过公开 SDK 声明界面入口、编写后台逻辑，并按需申请原生服务权限，无需修改宿主。[从 Hello 模板开始开发](plugin-sdk.zh-CN.md)，或查看 [SDK 类型定义](../plugins/sdk/nexterm.d.ts)。

## 本轮实现边界

- 已实现标题栏状态项、工具栏、侧栏、底部面板、主标签页、独立内容弹窗、自定义设置页、命令面板、快捷键和终端右键菜单；页面内容由插件 HTML/CSS/JavaScript 控制，业务逻辑运行在后台 Worker。
- 已实现安装、替换授权、启停、重载、排序、隐藏入口和卸载，以及按实例撤销网络能力与内存凭据。普通配置和安装包在本地 WebView 存储中保存，不参与配置同步。
- 插件设置入口位于对应插件条目内，通过独立弹窗显示自定义页面；多个设置页在弹窗内切换，不占用宿主的全局设置导航。
- 运行中插件的可见状态项常驻主窗口标题栏右侧（窗口控制按钮左边），不额外占行，专注模式也保留；隐藏、停用和卸载仍生效。
- 已实现通用「会话来源」扩展点：插件向原有会话栏发布动态列表，宿主提供搜索、刷新、设置入口、账号选择弹窗、标签页聚焦及连接状态。目录不进入本地会话库；插件停用或退出后清理列表，不关闭已有终端。
- 支持固定及运行时申请的精确 HTTPS origin；本机记住的动态授权可撤销，替换插件需重新确认。宿主提供 JSON 请求、内存秘密、Windows 凭据管理器和经用户确认的临时原生 SSH 会话。SSH 密码经一次性交接传给原生连接，不进入前端会话或工作区快照。
- 已实现动态目录增量追加，单来源可聚合 100000 项，宿主每页最多渲染 100 行；加载进度和全目录搜索不阻塞已加载主机的使用。
- 未实现在线市场、开发目录监视、跨平台系统凭据库存储、终端读写权限、动态注册界面扩展点或完整 MFA。开发迭代使用打包与替换安装。
- 当前仅面向可信插件。opaque iframe、CSP、Worker 和权限桥降低误用风险，不是已审计的恶意代码安全沙箱；不承诺阻断全部外传或进程级资源耗尽。

## 用户和开发者各自控制什么

插件作者决定业务逻辑、界面内容、交互方式和可用入口；使用者决定安装哪些插件、允许哪些能力、显示或隐藏哪些入口，以及在兼容区域内如何排列。Nexterm 负责窗口布局、生命周期、权限和原生终端。一个新的业务插件应当只依赖公开 SDK，不需要向 Nexterm 核心提交业务代码。

| 扩展位置 | 插件能做什么 |
| --- | --- |
| 标题栏、工具栏 | 在清单中声明按钮及其命令；后台可更新标题栏状态项的文字和提示。 |
| 侧边栏、底部面板、主标签页 | 提供自己的 HTML、CSS、JavaScript 视图；内容可以是表单、树、图表或完整工具页面，不限于宿主提供的控件。 |
| 设置页面 | 在插件条目的齿轮弹窗显示作者编写的设置页。 |
| 命令面板、快捷键、右键菜单 | 同一命令可有多个入口；按上下文决定是否出现或可用。 |
| 后台与会话 | 在不显示页面时刷新数据；经用户确认可打开临时原生 SSH 会话。SDK 不提供读取终端输出或发送任意输入的接口。 |
| 会话来源 | 为原有会话栏提供动态主机目录，由插件自行查询和检查授权，宿主统一显示并打开原生终端。无需另建资产浏览页面。 |

## 分发、运行与权限

- **本地安装。** 插件包携带清单、脚本和可选视图。安装时展示身份、版本、网络目的地和所需权限；支持升级、启停、卸载。每次替换均须重新确认。第一版不依赖在线市场，也不兼容 VSIX。
- **隔离运行。** 插件不直接访问宿主 DOM 或调用 Tauri。宿主通过版本化 SDK 提供界面注册、事件、配置、凭据、网络和终端服务。禁用或卸载应撤销入口和事件监听、停止后台任务；单个插件失败不影响已有终端会话。
- **凭据与会话。** 密码、访问令牌不应进入普通配置、日志或导出。持久凭据需要显式权限，仅后台可读写，并按插件、HTTPS origin 和键名隔离；卸载时清除。打开临时 SSH 会话不授予查看或操控其他终端的权力。
- **开发流程。** 实验版已提供公开 SDK 类型、最小模板、后台错误状态、重载和打包命令；目录直接加载、监视和更完整诊断作为后续能力。

## 如何验证一个扩展点

使用 [Hello 模板](../plugins/hello/)即可验证完整流程：打包安装，点击标题栏入口打开计数器，再点击页面按钮观察后台更新标题栏。将视图位置从 `tab` 改为 `dialog`，保持插件 ID 不变，重新打包并替换安装，可验证视图位置由清单而非宿主决定。最后停用插件，确认入口消失；已有原生终端不受影响。

若插件申请网络、持久凭据或打开 SSH 的权限，应分别测试拒绝、撤销、替换和卸载。使用自己的测试环境验证实际连接；不应把业务服务的地址、账号或数据写进公开模板或平台测试。
